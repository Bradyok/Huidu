# Cloning & recovery: one golden image for all C15/C35/C36, preserving per-unit identity

Goal: upgrade every unit to the latest firmware, capture **one golden master eMMC image**, and flash
it onto all same-model units — while **preserving each unit's unique identity** (device ID, MAC,
license, keys) so units stay individually addressable and licensed.

Status: **no device readback done yet.** Everything below about *what* is per-unit comes from
decompiling `System/BoxUpgrade` (`HSystemEnv::*`); the exact **partition map and offsets** still need
a real eMMC read (see "Get the image"). Nothing has been written to any unit.

## What must be preserved per unit (do NOT clone these)

Derived from the stock code — the identity chain is **ID → MAC**:

| Item | Path | Partition | Notes |
|---|---|---|---|
| **Device ID** (master identity) | `/root/Box/data/id` | rootfs/userdata | 16 bytes, read by `HSystemEnv::InitDeviceID` (`fread … 0x10`). Assigned at manufacture. e.g. `C15-C21-BF104`. **Everything else keys off this.** |
| **MAC address** | `/boot/dev_mac` | `boot` | **Derived from the ID** (`HSystemEnv::GenMACWithID`), applied at boot with `ifconfig eth0 hw ether %s`. Cached here; regenerable from the ID, but preserve to be safe. |
| License | `/root/Box/data/license.ini` | rootfs/userdata | per-unit licence |
| Device key | `/root/usb_dev/HDPlayerUsbExport/tips/device.key` | rootfs/userdata | per-unit key |
| Device info | `/root/Box/config/dev_info.xml` | rootfs/userdata | |
| Management password | `/root/Box/config/device_locker` | rootfs/userdata | the HDPlayer/SDK password (`device_locker.sh` clears it on old versions) |
| Server / name config | `/root/Box/data/permanentConfig.xml` | rootfs/userdata | cloud server + display name; may be per-site not per-unit |

The **`oem`** partition is also worth capturing per unit — the D15 DTB names it and vendor Rockchip
layouts keep a factory MAC/serial there; confirm on readback whether it duplicates `/boot/dev_mac`.

C15/C35/C36 use **no point-correction** (`device.xml SupportPointCorrection=0`), so there is no
per-cabinet screen-calibration blob to worry about; scan/gamma config is uniform for the model.

## What is common (safe to clone identically)

- Bootloader chain: `idbloader`/loader, `uboot`, `trust` — same per SoC/board.
- `boot` partition **except `dev_mac`**: kernel + DTB + `fpga.img` + `bootscreen` are model-common.
- rootfs/userdata **except `/root/Box/data/`, `/root/Box/config/{dev_info.xml,device_locker}`,
  `/root/usb_dev/.../device.key`**: the OS, libraries and the (upgraded) BoxPlayer app.
- `misc`, `recovery`: boot-control / recovery, common.

## Cloning workflow

```
Per source unit (the "golden" one), once it is on the latest firmware:
  1. Full eMMC read  → golden.img            (bootloader + all partitions)

Per target unit:
  2. Read & save that unit's identity:  /root/Box/data/id, /boot/dev_mac, license.ini,
     device.key, dev_info.xml, device_locker, permanentConfig.xml, (and the oem partition)
  3. Flash golden.img  (or just the common partitions)
  4. Restore that unit's identity files/partition
  5. Boot; verify: ID matches, `ifconfig eth0` MAC matches, licence valid, discovery shows the unit
```

If the ID is restored, `dev_mac` can be regenerated by the stock code — but restoring both avoids any
first-boot MAC flicker.

## Tooling (`tools/clone/`)

The steps above are implemented as safe, self-contained scripts (dry-run by default for
anything destructive, `--yes` to arm, and **no partition offsets are hard-coded** — they are
read from the device's GPT/sysfs at runtime). See `tools/clone/README.md`.

| Step | Script |
|---|---|
| 1. Golden read (USB/maskrom) | `rk_readback.sh <out> --loader MiniLoaderAll.bin` → `golden.img`, `<name>.img`, `partition-map.json` |
| 1'. Golden read (network) | `dd_readback.sh ssh:root@UNIT <out> --full` |
| 1a. Make flashable image | `build_update_img.sh --images <out> --loader … --from-map <out>/partition-map.json -o update.img` |
| 2. Save target identity | `identity_backup.sh <target> <bk> --oem-dev /dev/block/by-name/oem` |
| 4. Restore target identity | `identity_restore.sh <bk> <target> --yes` |
| 2–5. Orchestrate one unit | `clone_unit.sh --target ssh:root@UNIT --workdir <wd> --update-img update.img --yes` |

The per-unit preserve-list is the single-source-of-truth data file
`tools/clone/identity_files.list`.

## Get the image (two ways to read back)

**A. Maskrom + `rkdeveloptool` over USB (recommended — no shell needed, gets the bootloader too):**
```
# enter maskrom (short eMMC clock / maskrom test point), device enumerates as 2207:330d over USB-OTG
rkdeveloptool ld                              # confirm Maskrom
rkdeveloptool rl 0 <total_sectors> golden.img # read whole eMMC  (or per-partition with rd/rl + offsets)
# partition map comes from the loader / gpt; capture it too
```
This is also exactly the source for an RKFW `update.img` (afptool + rkImageMaker) to flash other units
with RKDevTool/`upgrade_tool`.

**B. Over the network via shell (needs telnet/ssh access — currently blocked):**
```
for p in /dev/block/by-name/*; do n=$(basename $p); dd if=$p | gzip > /mnt/usb/$n.img.gz; done
```
This is what the `packages/access-survey` package automates, once script execution on the unit works
(see `products/BoxPlayer/v7.11.18.0/UPGRADE_PROTOCOL.md` — the upgrade-execute path is still being
finished). Route A does not depend on that.

## Open items before building the golden image

These are the facts the scripts read at runtime and that still need a **real hardware run** to
confirm (the scripts fail loudly rather than guess any of them):

1. **Read one unit** (route A) to get the real partition map, sizes, and the `oem` contents.
   - Confirm the eMMC carries a **GPT** at LBA1 (assumed by `rk_readback.sh`; it aborts if the
     `EFI PART` signature is absent, which would mean a bare Rockchip parameter table instead).
   - Confirm the **`rkImageMaker` chip tag** for PX30/RK3326 (default `RK330C`) and the
     `parameter.txt` `CMDLINE`/`root=` (the `--from-map` synthesis rebuilds geometry only).
2. **Upgrade that unit to the latest** first (via HDPlayer.exe, or our client once execution works),
   so the golden image carries the newest app/firmware.
3. Decide clone granularity: whole-eMMC vs. common-partitions-only + identity restore.
4. Confirm whether `oem` holds an authoritative MAC/serial separate from `/boot/dev_mac`.
5. Build the RKFW `update.img` and validate a flash on the bench unit (restore its identity after).
